Getting past a login CAPTCHA in automation with session replay

A server-side CAPTCHA on the login page is good security and a real obstacle for UI automation. Here's how I made the suite reliable without weakening the app.

Sudipta Mohanty · SDET · 4 min read

The problem

The web client I automate has a server-side CAPTCHA on sign-in. That's the right call for security, but it means an automated test can't simply type a username and password and log in. Every test that needed a logged-in user was at risk of failing at the very first step. Those failures say nothing about the product.

I didn't want to ask for the CAPTCHA to be disabled in test environments, because then we'd be testing a different app from the one users get.

The approach: capture once, replay everywhere

  1. Capture. One authenticated session is created once and saved. In Playwright that's the browser's storage state: cookies and local storage.
  2. Replay. Every test starts in its own isolated browser context that is pre-loaded with the saved session, so it begins already signed in.
  3. Validate. Before the suite relies on the session, a quick check confirms it is still valid.
  4. Skip cleanly. If the session has expired, tests that need it are skipped with a clear message instead of failing.

What it looks like

A simplified illustration with Playwright for Python (not company code):

# illustrative only
import pytest
from pathlib import Path

STATE = Path(".auth/session.json")

@pytest.fixture(scope="session")
def auth_state(browser, base_url):
    if not STATE.exists():
        pytest.skip("No saved session. Capture one first (see README).")
    ctx = browser.new_context(storage_state=STATE)
    page = ctx.new_page()
    page.goto(base_url + "/dashboard")
    expired = "login" in page.url
    ctx.close()
    if expired:
        pytest.skip("Saved session has expired. Re-capture it, then re-run.")
    return STATE

@pytest.fixture
def page(browser, auth_state):
    ctx = browser.new_context(storage_state=auth_state)  # isolated per test
    yield ctx.new_page()
    ctx.close()

Why "skip" instead of "fail"

An expired session is a setup problem, not a product defect. If those tests failed, the run would turn red for a reason that has nothing to do with the release, and someone would waste time triaging it. A skip with a clear message says exactly what's wrong and what to do: re-capture the session.

Result: no false authentication failures in the regression runs. A red test means something real.

Things to watch

  • Treat the saved session like a secret. Keep it out of version control and logs.
  • Keep contexts isolated. Each test gets its own context, so one test's state can't leak into another's, even though they share a login.
  • Still test login itself. Session replay is for everything after sign-in. The login flow and the CAPTCHA behaviour deserve their own targeted checks.
