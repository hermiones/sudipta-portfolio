Every red test gets a label: classifying failures automatically

A failed test is a question, not an answer. Classifying every failure automatically means the defect register only holds real findings, and triage stops being a daily chore.

Sudipta Mohanty · SDET · 5 min read

The problem with "it's red"

When a regression run fails, someone has to open each failure and work out what happened. Most failures in a large suite are not product bugs. A locator changed, the test environment was slow, the data was stale or the test itself was wrong. If those all land in the defect register, developers stop trusting it.

Five categories

In the Playwright framework I built, every failure is classified into one of five buckets:

CategoryMeaningTypical signal
Product defectThe app did the wrong thingAssertion on behaviour or data failed with the page working normally
UI changeThe screen changed, the test didn'tLocator not found, element changed
EnvironmentThe test bed was unhealthyTimeouts, 5xx responses, connection errors
DataTest data was missing or staleExpected record absent, setup data invalid
Test issueThe test itself is wrongErrors inside test code or fixtures

Only product defects go to the defect register. The other categories are routed to whoever can fix them: test owners, environment owners or data setup.

How it works

The classifier hooks into Pytest's reporting step. When a test fails, it looks at the exception type, the message and where the error came from, then attaches the evidence. Here's a simplified illustration of the idea (not company code):

# conftest.py: illustrative only
import pytest

def classify(exc, text):
    if "Timeout" in type(exc).__name__ and "locator" in text:
        return "UI change"
    if any(s in text for s in ("ERR_CONNECTION", " 502", " 503", "net::")):
        return "Environment"
    if "test data" in text or "fixture" in text:
        return "Data"
    if isinstance(exc, AssertionError):
        return "Product defect"
    return "Test issue"

@pytest.hookimpl(hookwrapper=True)
def pytest_runtest_makereport(item, call):
    outcome = yield
    report = outcome.get_result()
    if report.when == "call" and report.failed:
        text = str(call.excinfo.value)
        report.category = classify(call.excinfo.value, text)
        # attach screenshot, trace and video for this test here

Real rules are richer than this, but the shape is the same: cheap, explainable rules first, with evidence attached so a human can confirm a category in seconds.

Evidence makes it trustworthy

Every failure comes with a screenshot, a Playwright trace and video. A label alone isn't enough. People need to see why the classifier decided what it did. With the trace open, confirming "UI change" or "product defect" is a few seconds' work instead of a re-run.

What changed

  • The defect register holds real findings, so developers take it seriously.
  • Triage time drops, because most failures arrive pre-sorted with evidence attached.
  • Patterns become visible. A spike in "Environment" failures is an infrastructure conversation, not twenty bug tickets.
